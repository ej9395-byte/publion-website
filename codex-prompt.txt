퍼블리온 출판사 홈페이지를 GitHub 에 새로 올리고 Vercel 에 배포해줘.

작업 디렉터리: ~/workspace/퍼블리온

── 반드시 지킬 것 ──────────────────────────────────
1. 파일 내용을 고치지 마라. vercel.json, .gitignore, HTML, CSS, JS 전부 읽기만 해라
   설정이 잘못됐다고 판단되면 고치지 말고 나에게 말해라
   (git remote 설정 변경은 예외다. 아래 3단계에서 지시한 대로만 해라)
2. 프로덕션 배포(--prod)를 내 확인 없이 하지 마라. 프리뷰까지만 하고 멈춰라
3. 도메인을 사거나 연결하지 마라. publion.co.kr 을 붙이지 마라
   Vercel 이 도메인 구매를 권해도 거절해라
4. git 이력을 다시 쓰지 마라. rebase, reset --hard, force push 금지
5. GitHub Pages 를 켜지 마라. 이유는 마지막 '알아둘 것' 에 있다

── 저장소 성격 ─────────────────────────────────────
- 빌드 도구가 없는 순수 정적 사이트다. 프레임워크도 번들러도 package.json 도 없다
- 46개 주소가 이미 HTML 파일로 존재한다
  index.html, books/, book/1~41/, journal/, about/, authors/
- 추적 파일 130개, 약 7.2MB, 커밋 6개가 이미 로컬에 있다
- vercel.json 과 .gitignore 는 이미 있다. 새로 만들지 마라
- 한글 파일명이 2개 있다 (도서별-소개글.md, 디자인시스템.md)
  푸시 후 GitHub 웹에서 두 파일이 보이는지 확인해라

── 1단계: 계정 확인 ───────────────────────────────
  gh auth status
현재 로그인된 계정 이름을 나에게 알려줘라.
로그인이 안 돼 있으면 `gh auth login` 안내만 하고 멈춰라.

── 2단계: 새 저장소 생성 ──────────────────────────
저장소 이름: publion-website
공개 범위: public

  gh repo create publion-website --public --description "퍼블리온 출판사 홈페이지"

같은 이름이 이미 있으면 덮어쓰지 말고 멈춰서 나에게 물어봐라.

── 3단계: 원격 교체 ───────────────────────────────
로컬에 예전 계정(gamsungsecretary-glitch)을 가리키는 origin 이 남아 있다.
지우지 말고 이름만 바꿔 보존한 뒤, 새 origin 을 붙여라.

  git remote rename origin old-origin
  git remote add origin https://github.com/<새계정>/publion-website.git
  git remote -v          # 두 개가 보여야 한다

── 4단계: 푸시 ────────────────────────────────────
  git branch --show-current       # main 이어야 한다
  git push -u origin main
  git rev-list --count --left-right origin/main...HEAD   # 0 0 이어야 한다

── 5단계: Vercel 연결 ─────────────────────────────
  which vercel || npm i -g vercel
  vercel whoami                   # 로그인 안 돼 있으면 vercel login 안내 후 멈춤

새 GitHub 저장소를 Vercel 프로젝트로 연결해라. 설정은 전부 비워라.
  - Framework Preset: Other (또는 No Framework)
  - Build Command: 비움
  - Output Directory: 비움 (저장소 루트)
  - Install Command: 비움
  - Root Directory: 비움

── 6단계: 프리뷰 배포 ─────────────────────────────
프리뷰 배포를 1회 실행하고 주소를 알려줘라. --prod 는 쓰지 마라.

── 7단계: 확인 ────────────────────────────────────
배포 주소로 아래를 실제로 요청해서 상태 코드를 확인해라. 추측하지 마라.

  a) /                                  200
  b) /assets/css/styles.css             200
  c) /assets/js/app.js                  200
  d) /assets/img/covers/cover-41.jpg    200
  e) /book/41/                          200
  f) /books/  /journal/  /about/  /authors/    전부 200
  g) /sitemap.xml                       200, <loc> 46개
  h) /robots.txt                        200
  i) 없는 주소 (/zzz/)                  404

  CSS 적용 여부를 파일 200 만으로 판단하지 마라.
  페이지를 실제로 열어서 배경이 흰색이고 제목이 큰 고딕체로 나오는지,
  링크가 브라우저 기본 파란색이 아닌지 눈으로 확인해라.
  스타일이 안 먹으면 자산 경로 문제다. 아래 '알아둘 것' 을 봐라.

── 알아둘 것 ──────────────────────────────────────
- HTML 안의 자산 경로는 루트 기준 절대경로(/assets/...)다.
  Vercel 은 루트에서 서빙하므로 그대로 맞는다.
  반대로 GitHub Pages 는 /<저장소이름>/ 하위에서 서빙하므로 전부 404 가 난다.
  그래서 Pages 를 켜지 말라는 것이다. 미리보기는 Vercel 만 쓴다
- HTML 의 canonical 과 sitemap 은 https://publion.co.kr 을 가리킨다.
  아직 연결되지 않은 도메인이다. 지금은 그대로 두고 고치지 마라.
  Vercel 프리뷰 배포에는 noindex 가 붙으므로 색인 문제는 없다

── 보고 형식 ──────────────────────────────────────
1. 1단계에서 확인한 GitHub 계정 이름
2. 새 저장소 주소
3. Vercel 프리뷰 주소
4. 7단계 a~i 결과를 표로. 실패 항목은 원인까지
5. 프로덕션 배포를 진행할지 나에게 물어보고 멈춰라
