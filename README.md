# 퍼블리온 Publion — 홈페이지

Claude Design 프로젝트 **Thames and Hudson 홈페이지 분석**의 `Publion.dc.html` 시안을
실제로 동작하는 정적 사이트로 옮긴 것입니다. 빌드 도구 없이 그대로 열립니다.

## 열기

```bash
node build/prerender.mjs && python3 -m http.server 4173
```

브라우저에서 `http://127.0.0.1:4173` 을 엽니다.
`file://` 로 직접 열면 동작하지 않습니다. 서버가 필요합니다.

데이터나 소개글을 고친 뒤에는 **반드시 `node build/prerender.mjs` 를 다시 돌립니다.**
정적 페이지 45개가 그때 다시 만들어집니다.

## 배포

GitHub 과 Vercel 로 올립니다. 코덱스에 붙여넣을 프롬프트가 `DEPLOY-PROMPT.md` 에 있습니다.

| 파일 | 용도 |
|---|---|
| `DEPLOY-PROMPT.md` | 코덱스용 복붙 프롬프트 + 배포 후 할 일 |
| `.gitignore` | 배너 배경 원본 47MB · PDF · `publion/` 제외 |
| `vercel.json` | 정적 호스팅 설정. 빌드 없음. 이미지 1년 캐시 |

저장소에 들어가는 것은 파일 122개, 6.9MB 입니다.

**배포 후 반드시 할 일**: `assets/js/views.js` 의 `SITE.origin` 이
`https://publion.co.kr` 로 박혀 있습니다. 실제 도메인이 정해지면 고치고
`node build/prerender.mjs` 를 다시 돌려야 canonical 주소와 sitemap 이 맞습니다.

## 검색·AI 답변 대응 (GEO · AEO)

핵심은 하나입니다. **ChatGPT·Claude·Perplexity 크롤러는 자바스크립트를 실행하지 않습니다.**
(Vercel + MERJ 대규모 측정, 2025. 벤더 확인은 없으니 방향만 신뢰합니다.
Gemini 는 Googlebot 기반이라 예외입니다.)

처음 구현은 자바스크립트로 화면을 그리는 방식이라, 이 크롤러들이 받는 본문이 **97자**뿐이었습니다.
정적 생성으로 바꾼 뒤:

| 주소 | 크롤러가 받는 본문 |
|---|---|
| `/` | 1,630자 |
| `/books/` | 3,375자 |
| `/book/23/` | 1,026자 |
| `/about/` | 1,073자 |
| `/authors/` | 1,293자 |

해시 주소(`#/book/23`)는 서버로 전달되지 않아 크롤링 대상이 될 수 없습니다.
실제 경로로 바꾸면서 색인 가능한 주소가 1개에서 **45개**로 늘었습니다.

함께 넣은 것:

- 페이지별 `title` · `description` · `canonical` · OG 태그
- `robots.txt` — 아무 크롤러도 막지 않습니다. AI 크롤러 차단이 인용을 줄인다는
  동료평가 측정이 있습니다 (arXiv:2604.27790, SIGIR 2026)
- `sitemap.xml` — 45개 주소
- 구조화 데이터 — Organization · WebSite · BreadcrumbList · Book(ISBN·정가·수상) · CollectionPage

**구조화 데이터를 AI 인용 목적으로 넣지 않았습니다.** 그런 효과를 보인 동료평가 연구는
없습니다. 유일한 실험은 구조화 데이터 벤더가 수행했고 JSON-LD 단독 효과는 미미했습니다.
검색 결과에 실제로 렌더링되는 기능과 데이터 정합을 위한 것입니다.

FAQ·HowTo 스키마는 넣지 않았습니다. 두 리치 결과 모두 폐지됐습니다(FAQ 2026-05, HowTo 2023-09).

### 배포 후에 해야 할 일

로컬에서는 확인할 수 없고 실제 도메인에서만 확인되는 항목입니다.

1. `assets/js/views.js` 의 `SITE.origin` 을 실제 도메인으로 바꾸고 다시 생성합니다.
2. 크롤러별 접근 확인 — robots.txt 가 아니라 실제 응답을 봅니다. CDN·WAF 가 조용히
   막는 경우가 있습니다. 한 번씩 요청해 상태코드와 응답 크기를 비교합니다.
   `GPTBot` · `OAI-SearchBot` · `ChatGPT-User` · `ClaudeBot` · `Claude-SearchBot` ·
   `Claude-User` · `Googlebot` · `PerplexityBot` · `CCBot` · 일반 브라우저(대조군)
3. 네이버 서치어드바이저에 사이트를 등록합니다. 네이버 AI 브리핑 인용의 약 17%가
   외부 웹사이트이므로 자사 도메인도 대상이 됩니다.
4. Google Search Console 등록.

접근 확인이 통과해도 "AI가 우리 사이트를 본다"고 말할 수는 없습니다.
크롤링 가능 여부와 실제 인용 코퍼스 포함 여부는 다른 문제입니다.
정확한 표현은 **"인용을 막는 요소는 없다"** 입니다.

### 다시 조판하기

```bash
python3 build/compose_banners.py
```

`assets/img/_bg/` 의 배경 원본 위에 표지를 다시 얹어 18장을 만듭니다.
배치는 세 가지입니다.

- `row` — 표지를 한 줄로. 좌우 여백 7.5% 를 남기고, 넘치면 표지 높이를 자동으로 줄입니다.
- `fan` — 세로로 긴 시리즈 타일용. 표지를 40% 씩 겹칩니다. 한 줄로는 들어가지 않기 때문입니다.
- `single` — 한 권만 크게. 히어로와 피처에 씁니다.

조판 후 표지가 안전 폭을 넘으면 스크립트가 중단됩니다. 잘린 채로 저장되지 않습니다.
올릴 책을 바꾸려면 스크립트 아래쪽의 도서번호 목록을 고칩니다.

### 히어로만 다른 규칙을 쓰는 이유

다른 자리는 CSS 가 비율을 고정해 잘림이 없습니다. 히어로만 높이가 620px 로 고정이고
폭이 화면을 따라가서, 화면이 좁을수록 좌우가 잘립니다. 그래서 두 가지를 맞췄습니다.

- 캔버스를 2000×800(2.5:1)로 잡아 실제 박스 비율에 가깝게 했습니다.
- `object-position: 68%` 로 잘림 기준을 표지 쪽에 뒀습니다. 375px 화면까지 표지가 온전합니다.

820px 이하에서는 흰 판이 배너를 거의 덮어 책이 흐리게 비쳤습니다.
이미지와 텍스트 판을 위아래로 나누고, 조작 버튼은 표지를 가리지 않도록 왼쪽으로 옮겼습니다.

### 무엇을 고쳤나

**머리 부분이 화면의 35%를 먹고 있었습니다.** 375px 기준 284px였습니다.
상단 띠·헤더·내비가 각각 두 줄로 접힌 결과입니다. 148px 로 줄였습니다.

- 상단 띠는 분야 나열을 빼고 배송 안내만 한 줄로 둡니다. 바로 아래 내비와 겹치는 내용이었습니다.
- 헤더에서 동작하지 않는 '검색'·'계정' 자리표시자를 감춥니다. 실제로 이동하는 스토어 링크만 남습니다.
- 내비 다섯 항목은 두 줄로 접히던 것을 한 줄 가로 스크롤로 바꿨습니다.

**44px 미만 터치 대상이 37개였습니다.** 지금은 0개입니다.
분야 칩, 정렬, 저널 목록 행, 푸터 링크, 히어로 인디케이터까지 손가락이 닿는 것은 모두 44px 이상입니다.
인디케이터는 보이는 굵기(4px)를 그대로 두고 누르는 범위만 넓혔습니다.

**마우스를 올려야 열리는 메가메뉴는 감춥니다.** 터치에서는 쓸 수 없습니다.
내비 항목을 누르면 해당 목록으로 바로 갑니다.

**히어로는 이미지와 텍스트 판을 위아래로 나눕니다.**
겹쳐 두면 흰 판이 배너를 거의 덮어 책이 뿌옇게 비쳤습니다.
조작 버튼은 표지를 가리지 않도록 왼쪽에 둡니다.

**분야 칩은 가로 스크롤입니다.** 여섯 개가 세 줄로 접히던 것을 한 줄로 폈습니다.

## 이미지 넣기

이미지 자리를 누르거나 파일을 끌어다 놓으면 채워집니다. 브라우저에
저장되므로 새로고침해도 남습니다. 슬롯을 고른 뒤 Delete 를 누르면 비웁니다.
표지 자리는 위 파일이 기본으로 깔려 있고, 직접 놓은 이미지가 있으면 그쪽이 우선합니다.

같은 id 는 같은 이미지를 공유합니다. 표지를 한 번 넣으면 홈·목록·상세·관련도서에
모두 반영됩니다. id 규칙은 Design SOP 7장과 같습니다.

| id | 맞춤 | 내용 |
|---|---|---|
| `cover-{도서번호}` | contain | 도서 표지 |
| `hero-1` `hero-2` `hero-3` | cover | 히어로 배너 |
| `subject-1` … `subject-5` | cover | 분야 타일 |
| `series-1` `series-2` `series-3` | cover | 시리즈 타일 |
| `journal-1` `journal-2` `journal-3` | cover | 저널 썸네일 |
| `feature-main` | cover | 피처 기사 |
| `promo-literature` `promo-store` | cover | 문학 · 스토어 프로모 |
| `mega-card-1` | cover | 메가메뉴 카드 |

저장은 브라우저마다 따로입니다. 확정 이미지가 나오면 `assets/img/` 에 넣고
슬롯에 `src` 속성을 주는 편이 낫습니다. 그때도 사용자가 놓은 이미지가 우선합니다.

## 블로그 글 연결

`assets/js/posts.js` 에 대표 블로그 10편과 퍼블리온 블로그 50편, 모두 60편이 들어 있습니다.
두 블로그의 RSS 에서 제목·날짜·주소를 가져온 것입니다. 누르면 해당 블로그로 이동합니다.

두 자리에 나옵니다.

- **저널 화면** (`/journal/`) — 60편 전체를 출처별로 나눠 보여줍니다.
- **도서 상세 '이 책의 이야기'** — 그 책을 다룬 글만 골라 붙입니다. 현재 15종에 붙어 있고
  『당신과 함께, 유럽』 10편, 『현금경영』 4편, 『위너 셀즈 올』 3편 순입니다.

연결은 글 제목에 도서명이 들어가는지로 판단합니다. 새 글이 올라오면 두 RSS 를 다시 읽어
`posts.js` 를 갱신하고 `node build/prerender.mjs` 를 돌립니다.

## 서점 구매 링크

도서 상세의 '책 소개' 아래 **구매하기** 블록에서 네 곳으로 갑니다.
스마트스토어만 먹 바탕이고 나머지는 테두리만 씁니다 (SOP 6장 — 한 화면에 기본 버튼은 하나).

| 서점 | 주소 방식 |
|---|---|
| 퍼블리온 스마트스토어 | 고정 주소 |
| 교보문고 | 상품ID 직링크. ISBN 으로는 열리지 않아 `data.js` 의 `kyobo` 값을 씁니다 |
| 예스24 | ISBN 검색. `dispNo` 파라미터가 없으면 첫 화면으로 튕깁니다 |
| 알라딘 | ISBN 직링크 |

교보 상품ID는 ISBN 으로 교보 검색을 걸어 얻었습니다. 인포크 링크에 실려 있던 실제 ID
8건으로 대조해 8/8 일치를 확인한 뒤 41종 전체에 적용했습니다.

신간을 추가하면 그 책의 교보 상품ID를 `data.js` 에 넣어야 합니다. 없으면 링크가 깨집니다.

## 신간 추가

Design SOP 9장 절차와 같습니다.

1. `assets/js/data.js` 의 `BOOKS` 에 항목 추가. `id` 는 겹치지 않게.
2. 표지 슬롯 `cover-{id}` 에 표지 이미지를 넣습니다.
3. 신간 5단은 `date` 기준 자동 정렬이라 따로 손댈 것이 없습니다.
4. `assets/js/intros.js` 에 같은 번호로 소개글을 추가합니다. 없으면 준비 중 문구가 나옵니다.
5. 표지를 `assets/img/covers/cover-{번호}.jpg` 로 넣습니다.
6. 교보 상품ID를 `data.js` 의 `kyobo` 에 넣습니다.
   `https://search.kyobobook.co.kr/search?keyword={ISBN}&target=total` 에서 첫 `S000...` 값입니다.
7. 히어로에 올릴 책이면 `HERO` 에 추가하고 가로로 긴 배너 이미지를 준비합니다.
   왼쪽 40% 는 텍스트 판이 덮습니다.
8. `node build/prerender.mjs` 를 돌려 정적 페이지를 다시 만듭니다.

## 시안과 다르게 한 부분

구현하면서 바꾼 것은 아래 네 가지입니다. 나머지는 시안의 수치와 문안을 그대로 옮겼습니다.

1. **의미 있는 태그로 교체** — 시안은 `div` 에 클릭을 걸지만 여기서는 `a` 와 `button` 을
   씁니다. 보이는 결과는 같고 키보드와 스크린리더로 쓸 수 있게 됩니다.
2. **정적 생성 + 실제 주소** — 45개 주소마다 HTML 파일을 만들어, 자바스크립트 없이도
   전부 읽히게 했습니다. 자바스크립트는 그 위에 상호작용만 얹습니다.
3. **모바일 레이아웃** — SOP 10장에 미적용으로 남아 있어 여기서 정했습니다.
   시안의 원칙(흰 바탕·검정 활자·얇은 괘선·강조색 하나·표지가 가장 강한 색)은 그대로 지켰습니다.
   자세한 내용은 아래 '모바일' 절에 있습니다.
4. **푸터 링크 연결** — 시안에서 눌리지 않던 푸터 항목 중 갈 곳이 분명한 것만
   연결했습니다. `채용` 과 `출간 예정` 은 대상이 없어 글자로 두었습니다.
5. **저널 실제 글 연결** — 시안의 저널 세 칸은 제목만 있는 자리였습니다.
   실제로 발행된 글 세 편으로 바꿨습니다.
6. **저널 화면 신설** — 시안에 없던 화면입니다. 블로그 글 60편을 모아 보여줍니다.
   홈 화면의 섹션 순서는 건드리지 않았습니다 (SOP 5장).
7. **구매하기 블록** — 시안은 상세 상단에 서점 이름만 한 줄로 두었습니다.
   책 소개 아래 별도 블록으로 옮기고 각 서점의 그 책 페이지로 바로 연결했습니다.
8. **동작 최소화 대응** — 시안의 `fadeUp` 은 `fill-mode: both` 라 애니메이션이
   실행되지 않는 환경에서 카드가 투명하게 남습니다. 동작 최소화를 설정한
   사용자에게는 애니메이션을 끄고 최종 상태를 보여주도록 했습니다.

시안에는 `cart` 상태와 장바구니 담기 동작이 남아 있으나 화면 어디에도 쓰이지
않아 옮기지 않았습니다. 상세 페이지의 구매 경로는 스마트스토어 링크입니다.

| 항목 | 도서목록(2026) | 시안 · 현재 사이트 |

표 번호가 뒤바뀐 건 사이트 도서번호와 도서목록 표 번호가 다른 것뿐이고,

잘못 붙은 표지는 없습니다.

대표 성함은 도서목록 판권면과 시안 모두 **박선영**으로 되어 있어 그대로 썼습니다.
