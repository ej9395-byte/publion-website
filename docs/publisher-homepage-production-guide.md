# 출판사 홈페이지 제작 가이드

퍼블리온 홈페이지를 만들며 정리한 재사용용 제작 방식입니다. 다른 출판사 홈페이지를 만들 때
이 문서를 먼저 복사하지 말고, 이 저장소의 최신본을 기준으로 읽은 뒤 프로젝트 상황에 맞게
적용합니다.

이 문서는 살아 있는 가이드입니다. 새 출판사 프로젝트에서 더 나은 방식이 생기면 아래
`업데이트 기록`에 날짜와 이유를 남기고 본문을 고칩니다.

## 1. 목표

출판사 홈페이지는 예쁜 표지 진열장이 아니라, 독자·서점 MD·기자·AI 검색엔진이 출판사와
개별 도서를 정확히 이해하게 만드는 원본 허브여야 합니다.

핵심 목표는 네 가지입니다.

- 전체 도서 목록을 한곳에서 탐색하게 한다.
- 각 도서 상세 페이지를 검색 가능한 독립 문서로 만든다.
- 블로그, 유튜브, 서점, 보도자료, 외부 소개 링크를 도서별로 연결한다.
- 자바스크립트가 꺼져도 본문과 링크가 HTML에 남게 한다.

## 2. 기본 구조

퍼블리온 방식은 정적 사이트입니다. 빌드 서버나 CMS 없이도 파일만으로 배포할 수 있게 만들고,
필요한 경우 나중에 CMS로 옮길 수 있도록 데이터와 화면을 분리합니다.

권장 구조:

```text
assets/
  css/styles.css
  img/covers/
  img/banners/
  js/app.js
  js/data.js
  js/intros.js
  js/media.js
  js/posts.js
  js/external.js
  js/views.js
build/
  prerender.mjs
docs/
  publisher-homepage-production-guide.md
book/{id}/index.html
books/index.html
journal/index.html
about/index.html
authors/index.html
index.html
sitemap.xml
robots.txt
```

역할:

- `data.js`: 도서 기본 정보, 분야, 시리즈, 히어로 노출 정보
- `intros.js`: 도서별 소개글
- `media.js`: 공식 유튜브, 언론·기관 추천
- `posts.js`: 출판사/대표 블로그 글과 도서 연결표
- `external.js`: 외부 유튜브, 외부 블로그, 서평 콘텐츠
- `views.js`: 브라우저와 정적 생성기가 함께 쓰는 화면 템플릿
- `prerender.mjs`: 실제 URL별 HTML 파일 생성

## 3. 자료 수집 순서

처음부터 디자인을 만지지 않습니다. 먼저 도서와 콘텐츠의 원본 자료를 모읍니다.

1. 도서목록 PDF, 엑셀, ISBN 목록을 확보한다.
2. 표지 이미지를 ISBN이나 출판사 원본 파일 기준으로 맞춘다.
3. 출판사 공식 블로그, 대표 블로그, 유튜브 채널, 보도자료를 수집한다.
4. 외부 유튜브·블로그·서평은 도서명과 저자명이 직접 확인되는 것만 후보로 둔다.
5. 구매 링크는 교보문고, YES24, 알라딘, 자사몰 순으로 붙인다.

수집할 때 지킬 기준:

- 도서명만 우연히 겹치는 콘텐츠는 제외한다.
- 저작권 위험이 있는 전문 낭독, 전문 요약 복제 콘텐츠는 제외한다.
- 미러 사이트는 원문 URL이 확인될 때만 사용한다.
- 공식 채널과 외부 채널은 섞지 않는다.

## 4. 도서 상세 페이지 구성

도서 상세가 사이트의 중심입니다. 홈보다 상세 페이지가 검색·인용·전환에 더 중요합니다.

권장 순서:

1. 표지, 분야, 제목, 저자, 핵심 문장
2. 구매하기 링크
3. 책 소개
4. 사양: 발행일, 쪽수, 판형, ISBN, 정가, 수상·선정
5. 목차
6. 저자 소개
7. 편집자·대표의 말
8. 공식 영상
9. 이 책의 이야기: 출판사/대표 블로그
10. 외부 소개: 외부 유튜브·블로그·서평
11. 함께 보면 좋은 책

없는 섹션은 빈 제목을 노출하지 않습니다. 데이터가 있을 때만 화면에 나타나게 만듭니다.

## 5. 글쓰기 원칙

출판사 홈페이지 문장은 서점 상세페이지 복사본이 되면 안 됩니다. 자사 홈페이지에는 그 출판사가
왜 이 책을 냈는지, 어떤 독자에게 닿기를 바라는지가 있어야 합니다.

도서 소개글:

- 200자 안팎으로 시작한다.
- 확인된 사실만 쓴다.
- 과장된 수식어, 느낌표, 이모지를 쓰지 않는다.
- 서점 문안을 그대로 옮기지 않는다.
- 독자가 책을 읽을 이유를 한 문장으로 분명히 남긴다.

편집자·대표의 말:

- 300~400자 안팎으로 둔다.
- 책이 시작된 질문, 출간한 이유, 독자에게 건네고 싶은 마음을 담는다.
- 판매 문구보다 출판사의 판단과 태도를 보여준다.

## 6. 디자인 원칙

출판사 사이트의 주인공은 표지입니다. 배경, 그라데이션, 장식이 표지보다 강하면 안 됩니다.

기준:

- 첫 화면에서 출판사의 정체성과 대표 도서가 바로 보이게 한다.
- 표지 이미지를 실제 상품 이미지로 정확히 보여준다.
- 분야·시리즈·저널 화면은 탐색이 빠르게 한다.
- 장식용 이미지는 책과 관계가 있는 분위기만 만들고, 글자나 가짜 책 표지는 넣지 않는다.
- 카드 안에 다시 카드를 넣지 않는다.
- 모바일에서 제목, 버튼, 출처명이 겹치지 않게 확인한다.

## 7. 검색·AI 대응

AI 검색 대응의 기본은 “자바스크립트 없이 읽히는 HTML”입니다. 단일 앱처럼 화면을 그리더라도,
배포 전에는 URL별 정적 HTML을 만들어야 합니다.

필수 항목:

- `/book/{id}/`처럼 각 도서 상세의 실제 URL을 만든다.
- `title`, `description`, `canonical`, OG 태그를 페이지별로 넣는다.
- `Book`, `Organization`, `WebSite`, `BreadcrumbList` 구조화 데이터를 넣는다.
- `sitemap.xml`에 모든 주요 URL을 넣는다.
- `robots.txt`에서 크롤러를 막지 않는다.

주의:

- 구조화 데이터만으로 AI 인용이 보장되지는 않는다.
- “AI가 인용한다”가 아니라 “인용을 막는 요소를 줄인다”가 정확한 표현이다.
- 해시 주소는 크롤링에 불리하므로 실제 경로를 우선한다.

## 8. 콘텐츠 연결 기준

콘텐츠는 출처별로 분리합니다.

공식 영상:

- 출판사 공식 유튜브 채널 영상
- 저자 인터뷰, 북트레일러, 북토크, 쇼츠 포함
- `media.js`에 도서별로 연결

공식/대표 블로그:

- 출판사 네이버 블로그
- 대표 블로그나 출판사 운영 블로그
- `posts.js`에 글 목록과 도서 연결표를 분리

외부 소개:

- 유명 유튜브 책 소개 채널
- 서점·언론·독립 블로그 리뷰
- 외부 네이버 블로그 원문
- `external.js`에 도서별로 연결

외부 링크 선정 기준:

- 제목, 본문, 설명 중 도서명 또는 저자명이 확인된다.
- 출처가 공식 채널이 아니어야 한다.
- 독자가 클릭했을 때 책 이해에 도움이 되어야 한다.
- 광고성, 복제성, 저작권 위험 콘텐츠는 제외한다.

## 9. 작업 절차

새 출판사 홈페이지를 만들 때는 이 순서로 진행합니다.

1. 원본 자료를 `source/` 또는 별도 작업 폴더에 모은다.
2. 도서 데이터 표를 확정하고 `data.js`를 만든다.
3. 표지 파일을 `cover-{id}.jpg` 규칙으로 정리한다.
4. 소개글과 편집자·대표의 말을 쓴다.
5. 공식 유튜브와 블로그 글을 전체 수집한다.
6. 도서명·저자명 기준으로 콘텐츠를 매칭한다.
7. 외부 소개 콘텐츠를 보수적으로 선별한다.
8. 화면 템플릿을 만들고 반응형을 확인한다.
9. 정적 HTML을 생성한다.
10. 링크 수, 누락 도서, 중복 URL, sitemap을 검증한다.
11. 커밋하고 배포한다.
12. 배포 URL에서 주요 페이지와 크롤러 접근을 다시 확인한다.

## 10. 검증 체크리스트

배포 전:

- `node build/prerender.mjs`가 성공한다.
- 생성된 정적 페이지 수가 예상과 맞다.
- 모든 도서의 상세 페이지가 존재한다.
- 표지 이미지가 깨지지 않는다.
- 구매 링크가 4곳 모두 연결된다.
- 공식 영상 수와 도서 연결 수가 맞다.
- 블로그 글 총수와 도서별 연결 수가 맞다.
- 외부 소개 URL에 중복이 없다.
- `sitemap.xml` URL 수가 페이지 수와 맞다.
- 모바일 폭에서 제목·버튼·출처명이 겹치지 않는다.

배포 후:

- 실제 도메인에서 홈, 도서목록, 대표 도서 상세, 저널, 소개 페이지를 연다.
- `SITE.origin`과 canonical URL이 실제 도메인과 맞는지 확인한다.
- 네이버 서치어드바이저와 Google Search Console에 등록한다.
- 주요 도서명을 검색했을 때 자사 페이지가 색인 가능한지 확인한다.

## 11. 운영 방식

신간이 나올 때:

1. `data.js`에 도서 정보를 추가한다.
2. `intros.js`에 소개글을 추가한다.
3. 표지를 `assets/img/covers/cover-{id}.jpg`로 넣는다.
4. 공식 영상이나 블로그 글이 있으면 `media.js`, `posts.js`를 갱신한다.
5. 외부 소개가 생기면 `external.js`에 추가한다.
6. `node build/prerender.mjs`를 실행한다.
7. 검증 후 커밋·배포한다.

블로그 글이 늘어날 때:

- RSS 또는 블로그 목록에서 제목, 날짜, URL을 다시 수집한다.
- 도서명 매칭을 다시 돌린다.
- 직접성이 약한 글은 연결하지 않는다.

외부 소개를 추가할 때:

- 원문 URL을 확인한다.
- 제목과 출처를 과장 없이 적는다.
- 공식 채널 콘텐츠가 아닌지 확인한다.
- 저작권 위험 콘텐츠가 아닌지 확인한다.
